# 传递型反链：文档与标题

跟进思源 3.8。原有列表项、引述块、超级块传递不变；本次只补「文档首段 / 标题下首段」两种。

- Issue：[siyuan-note/siyuan#10990](https://github.com/siyuan-note/siyuan/issues/10990#issuecomment-5087135778)
- 相关提交：[`88de47273`](https://github.com/siyuan-note/siyuan/commit/88de47273121ef57dddd5099ef72fb9eebe4dcbd)
- 思源源码：`D:\CodeProjects\SiYuan\App\siyuan`

## 规则

与官方一致：

1. 文档下**首个段落**仅包含块引用 → 反链单位为**整篇文档**。
2. 标题下**首个段落**仅包含块引用 → 反链单位为**该标题及其下属全部内容**。
3. 段落里还有正文、图片、标签等 → 不传递。
4. 同一文档已按规则 1 传递 → 不再按规则 2 传文内标题。

## 功能表现

命中后，这条反链按「文档」或「标题」展示，不再只显示那一行引用。

查询范围跟着扩大：

| 反链单位 | 关键字、关联定义块、筛选 |
|----------|--------------------------|
| 文档     | 该文档全部内容           |
| 标题     | 该标题 + 下属全部内容    |

设置里「查询标题下关联定义块」原来只覆盖「引用写在标题文字里」。本次：标题下首段传递时，**始终**按标题下属全文查询，不依赖该开关。开关语义不变，仍只管「反链在标题当中」的旧场景。

## 边界

- 不改列表项、引述块、超级块的现有传递。
- 不改提及模式。
- 不改「按反链块展示/排序」，不改成官方按文档分组。
- 不新增是否启用传递的设置，默认与官方一致。
- 父级是列表项时，仍走列表项传递，不升成文档/标题。
- 一篇文档 / 一个标题只保留一条反链，下属里其它引用合并进这一条。

## 实现

内核只在渲染层做了传递：`getBacklinkDoc` 返回的反链单位变成文档块 / 标题块，被并入的引用不再单独返回。插件按「一个引用块一条反链」统计和分页，不跟进就会出现「计数有、条目没有」。所以插件要自己算一遍同样的单位。

`src/service/backlink/backlink-propagation.ts`：

- 候选是 `type='p'`、`parentBlockType` 为 `d`/`h`、且 markdown 去掉块引用后只剩空白的反链块。父级是列表项的天然被排除。
- 「首个块」用 `getChildBlocks(父块 id)` 判定：它按文档顺序返回子块，文档取全部顶层块的第一个，标题取 `HeadingChildren` 的第一个，与内核 `isFirstBacklinkParentParagraph` 等价。
- 单位范围：文档取 `root_id` 全量；标题沿 `parent_id` 递归——思源建索引时把标题下方块的 `parent_id` 记成该标题（内核 `sql/database.go` 的 `HeadingParent`），所以递归闭包就等于 `HeadingChildren`。
- 文档优先、标题按覆盖范围从大到小去重，对应规则 4。

`backlink-data.ts`：

- `buildBacklinkPanelData` 里分两步。先把单位范围的 markdown 并进触发节点，让新出现的关联定义块能查到块信息；再由 `applyBacklinkPropagation` 把下属节点合并掉，并把节点的 `block` 换成文档块 / 标题块。
- `getBatchBacklinkDoc` 改为按节点去重归位：优先用内核返回的 `backlink.id`（文档单位的渲染 DOM 根节点是文档的第一个子块，只看 DOM 认不出整篇文档），再回退到父级列表项和单位下属块。
- 调 `getBacklinkDoc` 的定义块必须取自触发段落。换成单位里其它块引用的定义块，内核不会判定传递，拿回来的只有那一行。

内核低于 3.8.0 时整段不启用（`isKernelVersionAtLeast`）：旧内核不做这层传递，插件单方面合并只会丢条目。
